# Места — Петербург и пригороды

Отдельное статическое приложение: офлайн-карта, 9 368 заведений из исходного снимка OpenStreetMap, личная коллекция и обмен JSON. Сборка, серверная база, API-ключи и платные сервисы не нужны.

## Размещение на GitHub Pages

1. Распакуйте архив. Загрузите **содержимое** в корень репозитория: index.html должен находиться в корне, не внутри дополнительной папки. Загрузите также map-data.js и остальные файлы.
2. В настройках репозитория включите Pages: публикация из ветки main, папка / (root). Если ветка называется иначе, выберите её.
3. Дождитесь публикации и откройте адрес сайта. При первом посещении загрузится около 19 МБ файлов.
4. Дождитесь статуса «Доступно без сети». Теперь повторное открытие того же адреса работает без подключения, пока браузер хранит данные сайта.

Публикация не выполнена автоматически. Все пути относительные: приложение подходит для адреса вида username.github.io/repository/.

## Как пользоваться

- Общий справочник → категория или поиск по названию, адресу, кухне и заметке → карточка → «В мою коллекцию».
- «Добавить место» → название, категория, автор, заметка → «Выбрать точку на карте» → нажать на карту → сохранить. Без координат запись останется в списке.
- На телефоне снизу переключаются список и карта. На компьютере они видны одновременно.
- Зелёные числа объединяют соседние точки. Нажмите, чтобы приблизить карту; на максимальном масштабе откроется список группы.
- Список сортируется по близости к центру карты, не к местоположению телефона.
- «В список» отмечает записи для экспорта. Это не добавление в личную коллекцию: для сохранения откройте «Подробнее».
- «Импорт / экспорт» принимает JSON приложения и резервные копии NiceMeal с массивом places или placesData. Рецепты не импортируются. При совпадениях можно оставить свои записи или обновить их из файла.
- Кнопка удаления убирает место из коллекции; кратковременно доступна отмена.

## Подборка для посетителей сайта

Экспортируйте желаемые места, переименуйте JSON в public-places.json и замените одноимённый файл в репозитории. После публикации посетителям появится кнопка импорта подборки автора. Этот файл публичный: не включайте в него личные адреса или закрытые заметки. Личная коллекция посетителя сама в репозиторий не передаётся.

При каждом обновлении приложения **изменяйте номер CACHE в sw.js** (v3 → v4 и т. д.), включая обновления public-places.json. Откройте сайт с интернетом, дождитесь установки новой версии и перезагрузите страницу. Не удаляйте данные сайта для обновления: это удалит личную коллекцию.

## Данные и ограничения

Карта перенесена из последней доступной версии NiceMeal. Границы: 59.65–60.30° N, 29.35–30.85° E. Это Петербург и часть пригородов в указанном прямоугольнике, а не вся Ленинградская область. Дата, указанная в исходном наборе: 2026-11-01. Сведения о заведениях не проверены заново; некоторые адреса и категории отсутствуют, заведения могут закрываться. Геометрия карты упрощена.

Офлайн работают карта, список, поиск, добавление, редактирование и JSON. Внешние ссылки и построение маршрута в Яндекс Картах требуют интернета. Нет автоматического обновления OSM, геокодирования адресов, аккаунтов и облачной синхронизации.

Личные записи хранятся в localStorage этого браузера. Экспортируйте резервную копию перед сменой устройства, адреса сайта или очисткой браузера. Очистка данных сайта удаляет также офлайн-кеш. Приватный режим и политика браузера могут ограничить хранение. Нужен современный браузер с DecompressionStream; офлайн-перезапуск требует HTTPS или localhost.

## Локальный запуск

В каталоге приложения: `python3 -m http.server 8080`, затем открыть http://localhost:8080. Двойной клик по index.html не обеспечивает service worker и загрузку общей подборки.

## Проверено

В Chromium: карта и 9 368 записей, фильтр категории, добавление места без координат, сохранение после перезапуска, удаление, мобильная компоновка шириной 390 px, повторный запуск после остановки сервера. Проверки JavaScript: координаты, небезопасные ссылки, старый формат импорта, дубли ID, версия формата, экспорт/импорт, сохранность данных при ошибке хранилища. На реальных iOS/Android устройствах ещё не тестировалось.
